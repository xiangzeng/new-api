# 交接提示词骨架（model-handoff）

> 用法：把下面「提示词正文」整段填好，交给用户复制进外包 agent 会话（默认 Grok）跑。`《》` 是填空位，填完删掉尖括号。
> 命令/路径示例偏逆向与通用探索，按任务替换为项目实际可用的工具与路径。

---

## 提示词正文

你在 《项目名》 仓库。先按 `AGENTS.md` 启动协议读协议，本任务触发 《相关 skill，如 reverse-engineering + benchmark-dev；无则写 protocol-dev》，先读。禁止写产品代码，这是 《纯逆向 / 纯探索 / 纯抽取》 任务。

### 任务目标

《一句话说清要产出什么。》 逐项要拿到：

1. 《要点1（含要素：默认值 / 范围 / 步进 / 映射公式 / 字段定义 …）》
2. 《要点2》
3. 《…》

对标/覆盖清单（逐项都要）：《列全所有目标项，不留“酌情”。》

### 已完成、别重做（直接引用/扩展）

《把主会话侧已钉死的结论列出来，附文件与章节；防止外包重复劳动或产出矛盾结论。》
- 《结论A（来源: 文档/章节）》
- 《结论B》

### 数据来源

《代码/二进制/资源/日志的精确路径。若涉及逆向，给出框架路径与可靠性说明（是否砸壳、是否加密、环境限制等）。》

```
《路径清单》
```

### 重点目标 & 定位线索

- 《目标类/文件/模块 A：关注哪些属性/方法/符号/字段 → 预期在哪找到关键常量或定义》
- 《目标 B：…》

### 可跑命令 / 配方（能给全就给全）

```bash
《按任务填写。逆向例：nm / objdump / otool / strings、rip 相对常量解析、swift demangle 等。
  通用例：rg 范围、jq 抽取、python 解析脚本、git log/blame 配方等。
  能抄就给全，避免外包临场猜命令。》
```

### 输出要求

1. **结构化写**到 《指定路径，如 docs/handoffs/<slug>-data.json 或 extracted-resources/xxx.json》：每项含任务约定字段（例：`default / range / steps / mapping / constants / source / confidence`）。
2. **追加分析章节**到 《指定文档路径与章节》，逐项**标来源**：`(来源: 文件路径 / 符号 / 地址 / 章节)`，深度对齐现有已钉死章节。
3. **每项标置信度**。⚠️ 《若源受限、跨环境、合成视口、加密或间接推断》 → 必须标来源 + 「需在目标环境确认」，不得写成已证实事实。
4. **拿不准就升级**：现有信息不足以定论的，**列出需要更深工具（如伪代码反编译）或真机/人工确认的具体项**，不要编。
5. 《若有任务档案》 完事更新 `docs/tasks/xxx.md` 台账（只记事实进度，不写主观评价）。

先复述你的分析计划（要查哪些、预期在哪找到关键结论），再动手。

- [ ] 记入 task-dossier 台账（若有档案）
