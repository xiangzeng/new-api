## 提示词正文

你在 《项目名》 仓库。先按 `AGENTS.md` 读协议；本任务涉及 《相关 skill，如 reverse-engineering + benchmark-dev；无则写 protocol-dev》，先读。这是 《纯逆向 / 纯探索 / 纯抽取》 任务，不写产品代码。

### 任务目标

《一句话说清要产出什么。》逐项要拿到：

1. 《要点1（默认值 / 范围 / 步进 / 映射公式 / 字段定义 …）》
2. 《要点2》

覆盖清单（逐项都要）：《列全所有目标项》

### 已完成，别重做

- 《结论A（来源：文档 / 章节）》
- 《结论B》

### 数据来源

《代码 / 二进制 / 资源 / 日志的精确路径；逆向任务写明是否砸壳、是否加密、有哪些环境限制。》

```
《路径清单》
```

### 重点目标与定位线索

- 《目标 A：关注哪些属性 / 方法 / 符号 / 字段，预计在哪找到关键常量或定义》
- 《目标 B》

### 可跑命令

```bash
《能给全就给全。逆向：nm / objdump / otool / strings / swift demangle、rip 相对常量解析等；通用：rg、jq、python 解析脚本、git log / blame 等。》
```

### 输出要求

1. 结构化数据写到 《路径，如 docs/handoffs/<slug>-data.json》，每项含 《字段，如 default / range / steps / mapping / constants / source / confidence》。
2. 分析追加到 《文档路径与章节》，深度对齐已有章节，每项标来源：`(来源: 文件路径 / 符号 / 地址 / 章节)`。
3. 每项标置信度。《来源受限 / 跨环境 / 加密 / 间接推断》的结论标「需在目标环境确认」，不写成已证实的事实。
4. 信息不够下结论时，列出需要更深工具（如伪代码反编译）或真机 / 人工确认的具体项，不要编。
5. 《有任务档案时》完成后在 `docs/tasks/xxx.md` 台账记录事实进度，不写主观评价。

先复述分析计划（要查哪些、预计在哪找到关键结论），再动手。
